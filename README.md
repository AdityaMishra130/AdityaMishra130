# 🔪 THE DARK PASSENGER

Every developer has something that keeps pulling them back to the keyboard.

For me, it's the obsession with understanding **how things work underneath**.

That instinct is my version of the **Dark Passenger**.

Not something destructive.

Something analytical.

Something that asks:

```text
Why did this fail?

Where is the pattern?

Can this be simplified?

Can this be faster?

What happens at the edge case?

What happens if everything goes wrong?
```

And then...

```text
Open Editor.
Analyse.
Implement.
Test.
Break.
Fix.
Repeat.
```

When I encounter a problem, I don't immediately start coding.

First comes the investigation.

```text
┌───────────────────────────────────────────┐
```

The goal isn't to write the longest solution.

# ⚖️ THE CODE RULES

Every good developer needs rules.

Mine are simple.

### Rule #01

> **Never code before understanding the problem.**

### Rule #02

> **If there's a pattern, find it.**

### Rule #03

> **If the code can be simpler, simplify it.**

### Rule #04

> **If the solution is slow, investigate why.**

### Rule #05

> **Edge cases are evidence. Never ignore evidence.**

### Rule #06

> **Clean code leaves less evidence behind.**

### Rule #07

> **A bug is not a failure. It's a new case file.**

### Rule #08

> **Never stop learning.**
